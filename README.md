# semi-cobot

A responsive component inventory and PCB inspection workspace. Built with React, Vite, Three.js and Lucide icons. UI guidance from [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill).

## Run locally

Requires Node.js 22.12+.

```sh
npm ci
npm run server
# In a second terminal
npm run dev
```

Open the Vite URL. The API server binds only to `127.0.0.1:5174`.

## Included

- **Connected flow (redesign v2, see `deliverables/semi-cobot-redesign-workflow-architecture.pdf`):** Overview shows one line from part master and internal stock → BOM tool → saved lists → material → factory line → assembly → testing → final product with live counts (`src/ProcessFlow.jsx`). Every production job links back to its BOM (Open its BOM) and keeps its quote number and kit summary.
- **BOM tool steps:** Components (required) → Bare PCB (optional) → Enclosure (optional, with the mould on the same page) → Quotation. **Upload BoM or Gerber** in Components takes an Excel or CSV BOM, an `ibom.html`, or a board: a Gerber ZIP or layer files (with its BOM, `.pos`, `.kicad_pcb` or `ibom.html` inside), a `.kicad_pcb` or a placement file; a board becomes the BOM lines, joins Board studio and sets the bare PCB. Each step opens with a one-line guide. A Gerber uploaded in step 1 is sent on automatically: the board joins Board studio without leaving the BOM tool, its parts become the BOM when the BOM is empty, and its size sizes the enclosure.
- **Mould** (`src/MouldStep.jsx`, `src/mould.js`), shown under a custom moulded enclosure: plastic per enclosure, shot weight, cooling and cycle time, clamp force, output per hour, shots for the run and the SPI tool class that lasts it; the moulded cost appears only from your resin price and machine rate, and tooling and the moulded unit price come from the mould maker's quote. The mould maker list is the Vendors page's mould makers.
- **Quotation step:** a checklist of what is priced, **Save list** and **Continue to production** (customer and requested delivery).
- **Ask quote** (`src/rfq.js`): a BOM line whose offer is from an authorised distributor (or a registered vendor) has a one-click Ask quote; the purchase list has one per supplier for all its lines. It opens a written-out request for quotation (part numbers, manufacturers, quantities, references, delivery date, project and your company details from the quotation form) in your mail program, addressed to the supplier's quote email from the Vendors page; nothing is sent until you press Send.
- **Saved lists** page (`src/SavedLists.jsx`, `src/savedLists.js`): every saved BOM with status (draft, quoted, ordered, archived) and revision; open it back in the BOM tool exactly as it was, duplicate it, or follow the job it became.
- **Production chain:** incoming check, QA incoming, kitting, storing, SMT, PCBA, THT, wave soldering, QA line, assembly, testing and final QC and pack (`STAGES` in `src/production.js`), shown as five groups with a "Now / next" line; rework at quality gates, serial numbers at PCBA.
- **Where prices come from:** 1 internal stock (always first), 2 authorised distributor APIs, 3 products registered vendors list on the Vendors page (offers marked "Registered vendor"), 4 the open market (SerpApi Google Shopping). Open-market listings are kept only when the exact part number is a whole token of the title, the listing is not a kit, module, socket or "compatible"/"replacement" item, one per seller, with pack listings priced per piece (`filterSerp` in `api.mjs`); prices are not restricted. The part overview says how many listings were hidden and why.
- **Vendors** page with the **vendor register** (`src/Vendors.jsx`, `src/vendors.js`): every vendor kind; register a vendor, describe its capabilities and list the products it has (MPN, stock, price in ₹ or $, MOQ, lead time).
- **Help** page (`src/Help.jsx`): quick start, the BOM demo chapters, where prices come from, every production stage, every page with a link and common questions. The intro page lists what a user can do, step by step.
- **Part master** is the menu name of the component databank (old `#Component directory` links still open it).
- BOM tool (second menu item; `src/BomTool.jsx`, overview `src/BomOverview.jsx`, purchase list and bids `src/BomCart.jsx`, pricing `src/bom.js`, scores `src/bomScores.js`, quotation `src/quotePdf.js`). **Analysis view:** one card with the project name and a summary line (lines · % MPN matched · production units · BoM cost · parts at risk), **Upload BoM** and **Add all to list**, and a compact, searchable, sortable grid: picture and MPN, brand, available stock, the four scores, unit price and one action per line (Add to list, Bid for excess offers, Get price). Description, selected supplier, required quantity, total and more are optional columns (Columns) or in the expanded line; a risky part shows "· Risk" with its reasons. **Scores** are 0–100 weighted factors from reported data only (weights documented at the top of `src/bomScores.js`): resilience (stock coverage, distributors with stock, lifecycle, factory lead time), quality (source traceability, condition, certificate of conformity, datasheet, manufacturer, compliance data), economic (against best and median price, order waste), sustainability (RoHS, REACH, lifecycle, waste); "Not available" when under 60 % of a score's weight is known. **Component overview** (click a line): part number, maker, description, suggested alternative with the compatibility checks to make, General / Availability / Lifecycle & Compliance cards (HS code from the supplier's HTS code), and **Offers Across All Markets**: every distributor offer plus Google Shopping listings (one SerpApi search per opened part, cached six hours), offers you enter (EMS / OEM-ODM excess, broker; with price in INR or USD, shipping, date code, condition, certificate, contact), each with its market type, stock, MOQ, every price break, shipping (quoted, your supplier rule, or "Not quoted"), lead time, date code, an **uncertainty** score (source, part-number match, stock reported, price against the distributors) and actions (Use for BOM, Add to list, Bid, Chat with Seller by email or WhatsApp, Open listing); the **Best to get** offer is marked. **Pricing:** own stock first at its inventory price, the rest from the chosen or recommended offer at the quantity actually ordered (MOQ, multiples) and its price break; missing prices, a missing inventory price or an own-stock shortfall are flagged and left out, never counted as zero. Markup on cost or gross margin on price (labelled; margin capped at 95 %) per line, for the PCB and by default. **Bare PCB** (optional): FR-4, FR-4 high-Tg, aluminium core or polyimide flex, a board type or this board's size; counts once a price is entered (an estimate can be taken on purpose). **Shipping:** supplier shipping once per supplier order (flat charge, free above), delivery to the customer, charged at actual cost by default or a set amount, or **Offer Free Shipping**; totals show component cost, PCB cost, selling subtotal, actual shipping, shipping charged, customer total (= subtotal + shipping charged) and net profit (= customer total − components − PCB − actual shipping). **Purchase list** (not a cart: nothing is ordered) grouped per supplier, with CSV export for each supplier's BOM upload, **bids** with status and email. **Quotation PDF** with selling prices only: unpriced items print "Price on request", unknown shipping "To be confirmed", free shipping "Free"; no costs, markup, suppliers or profit. Amounts you type keep their currency; INR uses the live rate with its source and time.
- Bare PCB quote (`src/PcbGerber.jsx`, `src/gerberQuote.js`, options in `src/bom.js` `PCB_SPEC`): the options of a fab's standard-PCB form (JLCPCB layout: material, layers, size, product type, designs, delivery format, thickness, mask colour, silkscreen, finish, copper weights, via covering, smallest via, tolerance, marks, gold fingers, castellated holes, edge plating, impedance, track/spacing, build time), limited to what each material allows, with itemised charge details and build days. **Upload Gerber** (ZIP or layer files) draws the bare board in 2D, top or bottom (mirrored, as seen from below), in the chosen mask, silkscreen and finish, and fills the size, copper layers and via option from the files. A BOM loaded from a board in the workspace (the board in the 3D view) brings its bare board along with no upload: from the board's Gerber files when it keeps them, from the faces drawn at import, or drawn from the board model (outline, tracks, pads, holes, part outlines as legend) for KiCad, placement and reference boards (`src/bareBoard.js`); it is redrawn after a reload, and an uploaded set replaces it. Prices are rough estimates until the fab's quote is entered.
- BOM demo tour (`src/BomTour.jsx`, data and steps in `src/bomDemo.js`): **Watch the demo** in the BOM tool, **Watch the BOM demo** in Help, or the main tour's BOM step. A priced demo BOM (nine real parts, distributor and marketplace offers, an excess offer, an obsolete and a low-stock part, a bare PCB from the sample Gerber, shipping rules) replaces the user's BOM for the length of the tour and is put back afterwards, also after a reload mid-demo. Sixteen steps with the page dimmed and the feature spotlighted, a list of every step (current one marked, any one can be opened), an illustrated card, and Play to advance every 7 s; demo prices are illustrative and no supplier is called.
- INR and USD: the top-bar switch shows every price on the site in rupees or dollars. Prices are kept in dollars and converted with the live rate from `GET /api/fx` (open.er-api.com, cached 12 hours; an `FX_RATES` secret fixes the rates instead, `FX_LIVE=off` keeps the approximate defaults).
- Inventory has two sections: **Own stock** (part numbers, units, stock value, parts needing attention, then the parts table) and **Production** (`src/BoardFlow.jsx`): every job's boards in production, completed, ready for dispatch and dispatched, a step to move boards on (with a courier note on dispatch) and the dispatch log. The overview shows the same four counts.
- Real data only: a new workspace starts empty, with a getting-started panel (import Excel, add a component, or **Load sample data**). Sample components and jobs saved by earlier versions are removed once; Integrations → Sample data loads or removes them on request.
- Product tour (`src/Tour.jsx`): first sign-in walks through the overview, BOM tool, currency switch, inventory, studio, directory, production and alerts, opening each page and highlighting its menu item. Help → **Take the tour** runs it again.
- Overview dashboard (`src/Bento.jsx`, data helpers in `src/bentoData.js`): inventory value or unit count by storage location, share of each category, stock health, coverage against minimums, the parts that need attention, restock goals, stock per category against its minimum, the current board with a live 3D preview, and value or units by category. Everything is computed from the inventory records; the Value/Units switch changes the basis.
- Production capacity page (machines in process order, each pictured from its 3D model (src/machineView.js renders the factoryModels.js machines once per status): each SMT line as one unit showing the whole line with its stations loader → printer → SPI → pick-and-place → reflow → AOI → X-ray named under them, then wave and selective solder, then the ICT press and flying-probe tester; the signal tower shows the status; floors saved by the first version are rebuilt this way): how many days the last finished job took, which machines are running, idle or in maintenance, and a live possibility estimate (Likely, Tight, Not by that date) with the start date, finish date and reasoning when another board company asks for a job. Booked jobs take the free line; marking a job finished releases its machines.
- Supplier comparison: `/api/compare?mpn=` asks DigiKey, Mouser, Nexar, TME, Master Electronics and Google Shopping (SerpApi) at the same time, and each supplier fails on its own. The studio inspector beside the 3D model and the part dialogs show the result as a radar chart of price, stock, delivery, order size and trust per seller, with a ranked offer table. Non-USD prices are converted at approximate rates (override with `FX_RATES`). SerpApi results are cached for six hours.
- Gerber import (Import blueprint → a .zip of the fabrication set, or select every layer file): RS-274X Gerber with X2 attributes and Excellon drills, from KiCad, Altium, Eagle or EasyEDA names. The outline (with arcs and cut-outs), copper, solder mask, silkscreen and drill holes are painted onto both faces of the 3D board, and holes of 2 mm and up are cut through. Components come from Gerber X2 pad attributes (`%TO.P`/`%TO.C`), an X3 component layer, or a pick-and-place file in the same ZIP, aligned to the Gerber origin by matching pads. Without any of those the board is still exact, with no components. Sample: `public/samples/sample-gerber.zip` (regenerate with `node scripts/make-gerber-sample.mjs`).
- Part numbers from the Gerber set (`src/bomFile.js`, `looksLikeMpn` in `src/blueprint.js`): every part gets its manufacturer part number from, in order, the X3 component layer or X2 component attributes on the copper pads (`CMPN`, `CMfr`, `CVal`, `CFtp`), a BOM file in the ZIP (CSV, TSV or Excel; found by its name or by its Designator and part-number columns; JLCPCB, KiCad, Altium and EasyEDA layouts; designator lists and ranges such as `C1, C2` or `R1-R4`; DNP lines skipped; LCSC, DigiKey and Mouser numbers kept as the supplier part number), or the placement file. A Value that is really a part number (KiCad often writes `STM32F407VGT6` or `SS14` there) counts as the part number; passive values such as 10k, 4K7, 100nF, 16MHz or 3.3V stay values. The import note says how many parts got part numbers and from which file.
- Parts that come with a designator only (many KiCad Gerber sets carry `U1, pin 3` and nothing else) are named from their designator and pad pattern, for example "Resistor · 0805", "Integrated circuit · SOIC-8" or "Relay · 5-pin through-hole" (`src/partName.js`); boards saved earlier are named the same way when the app opens. Gemini is not used in Board studio: part data comes only from the files. When the Gerber layers carry only designators, Board studio says so and asks for the KiCad project files.
- Part data comes from the Gerber package: nested ZIPs inside the upload are opened, the KiCad board file (`.kicad_pcb`) inside the ZIP or imported with the Gerbers gives each designator its value, footprint and part-number field, and a KiCad Interactive HTML BOM (`ibom.html`, `src/ibom.js`) gives every designator its value, footprint and any part-number or manufacturer field (values such as ATmega8-16PU, L7805 or BC847 become part numbers; footprints such as R_1206_HandSoldering become 1206).
- New part numbers join the Part master by themselves, from imported boards and Gerber sets, BOM files and Gemini suggestions (confidence 60 % and up), marked "Added automatically" with where they came from (`learnParts` in `src/partDetails.js`). Part numbers the part master already has are not duplicated and nothing saved is overwritten.
- Gerber sets with no component data (no X2 attributes, component layer or placement file) still get components: every solder-mask opening becomes a pad, drills mark through-hole pins and vias, pads cluster by shape and pitch, facing rows join into DIP/SOIC/QFP packages, and closed silkscreen outlines split or join groups (`src/gerberInfer.js`). Each inferred part gets a package such as DIP-28, SOIC-8, Header 1x8 or 0603, and Gemini then suggests the real part numbers automatically.
- Board knowledge: a reviewed knowledge base of 61 board types (computing, microcontroller, power, motion, communications, consumer and industrial) in `public/data/board-types.json`, each with recognition signals, sections, typical parts with values and example part numbers, and review checks. The studio recognises the open board's type and lists the supporting parts each chip and connector needs (decoupling, bulk and load capacitors, pull-ups, USB-C CC resistors, ESD and fuses, gate resistors, LED resistors), what is already placed near it and what is missing. **Add missing parts** places them on free board space beside their chip, shown translucent blue (dashed in 2D) and priced in the market chart; **Remove suggested** takes them off again. The **Board types** page lists and searches every type. Rebuild the data with `node scripts/make-board-types.mjs <journal>`.
- Separate the layers (stacked-layers button in the 3D studio): the board pulls apart into components, silkscreen, solder mask, copper circuit and core for both sides, each labelled, with a legend to show or hide layers ("Circuit only", "Components only"). Gerber boards keep their files (gzipped) so each real fabrication layer is rebuilt for this view.
- Package-specific 3D parts: marked IC tops with pin 1, DIP notches, capacitors at their real size (radial and snap-in cans sized from capacitance × voltage or the footprint diameter, SMD aluminium cans on their base, tantalum cases A–E with the anode band, film boxes by lead pitch; ceramic chips keep their case code; saved boards are upgraded on load; `capacitorSize` in `src/blueprint.js`), chip passives with tin end terminations, header pins, USB and DC jack shells, HC-49 crystals, TO-220 tabs, module shield cans and tactile switches (`src/partModels.js`).
- Market chart under the 3D studio: a table with one row per component and one column per supplier (DigiKey, Mouser, TME, Master Electronics, then other sellers) showing the unit price with stock below, the cheapest price highlighted, total stock, and how many boards the market can supply (limited by the scarcest part). It queries the distributor APIs only (three at a time, cached); **Compare** on a row adds Google Shopping and the radar chart.
- Gemini identification: **Identify with Gemini** in the studio sends the footprint evidence of unidentified parts (pad count, rows, pitch, pad and body size, through-hole, designator, any package or value) to Gemini through `/api/identify` and stores the suggested type, package, part number, alternates and confidence per board. Suggestions only fill in parts that had no part number, and they then drive inventory matching, part knowledge and the market chart. Uses the Interactions API with `gemini-3.8-flash` and falls back to `gemini-3.6-flash` and `gemini-3.5-flash` when it is busy (set `GEMINI_MODEL` to pin one). Server env: `GEMINI_API_KEY`.
- 3D detail: gull-wing leads, metal end caps on passives, through-hole pins with solder joints on the back, solder on SMD pads, copper tracks as ribbons with vias on both sides. Boards without routing data get illustrative routing; the flip button shows the back side of every board. A full-screen button opens the 3D view on its own.
- Production line (Board studio → **Line**; planning in `src/factoryLine.js`, view in `src/FactoryLine.jsx`, one module per machine in `src/factory/`): PCB loader → solder paste printer → SPI → pick-and-place → reflow oven → AOI → X-ray on one straight conveyor, inside a closed factory hall (four walls, roof trusses with skylights and high-bay lamps, ventilation duct, roll-up loading door, fire exit, supervisor office, reel racks, dry cabinets, pallet racking, ESD benches, an AGV; the camera stays inside). Boards flow through on a schedule (one board per machine, transfers between them, boards spaced in the continuous oven); signal towers show running, waiting or a failed check. The plan works out each machine's process for the open board: stencil thickness and aperture area ratios, paste deposits and SPI volumes, the placement program, a reflow recipe (zone setpoints and conveyor speed) that meets the SAC305 profile, AOI checks (offset, rotation, polarity, solder), and X-ray void checks for BGA and bottom-terminated parts (boards without hidden joints get a sample of their three largest leaded ICs). The X-ray computer, on the line and in the machine view, shows the live X-ray image of the part under the tube: ball grids, thermal pads or gull-wing joints, with voids sized to the measured void %. Shows takt and bottleneck, boards per hour, first-board time and first-pass yield. Click any machine to open its inner view: the machine's own cycle in 3D with its steps and process data. The X-ray computer's screen shows in the corner of its view, with each frame read out row by row before the oblique views. The line stands in a factory hall (epoxy floor, safety lanes, wall, racks, lamps); the reflow oven's exhaust stacks fume and its openings vent flux vapour. Full screen from the button at the end of the toolbar. Inspection results are simulated: repeatable per board, and driven by the paste (small apertures print less paste, a starved or uneven joint fails AOI).
- Light and dark themes (sun/moon button in the top bar), remembered per browser and following the system setting by default. Both pass WCAG AA contrast on every page.
- Production estimate calculator: each job runs through paste print, pick and place, reflow, AOI and test stages. Completing a stage re-projects the finish from the real pace; the last stage finishes the job, frees its machines and adds it to the history. Estimates use the last three finished jobs, newest weighted most. With **Auto calculator** on, stages complete as their planned time passes and queued jobs move up and start on their own.

The run reports the worst placement error. **Export** saves the gripper program as CSV (step, designator, tool, grip width, pick and place coordinates in mm, rotation). **Import** runs a gripper program, or any pick-and-place CSV with a Designator column, in the file's order (or its Step column).

Moving the cursor over any component identifies it: a tooltip beside the cursor and the inspector panel show the reference, part name, package, stock status and, for diodes, the electrical summary and cathode orientation. Clicking opens full details. A keyboard-accessible, searchable component list offers the same workflow.

Component families and body sizes are inferred from reference designators and package names. Imported boards are stored per browser (up to 12) and can be switched or removed in Board studio.

The page is rendered in the browser, component outlines are detected from the pixels, PDF text labels are attached to the nearest shape, and the result becomes an interactive board whose surface is the picture itself, with 3D bodies standing on each detected component. Give the real board width in millimetres for correct scale. When `ANTHROPIC_API_KEY` is configured on the server, the page is sent to Claude vision (`claude-opus-5-5` by default, override with `ANTHROPIC_MODEL`) which names and classifies every component and guesses the form factor; without it, or if the request fails, the local detector runs. A Source filter (All, Part master, Saved, Inventory, Boards) and the full component catalogue (10 categories, 101 types, 416 subtypes, with counts) narrow the list; every part is sorted into the catalogue from its part number family, package, description and part-master family. The list shows 100 rows at a time. ## Live supplier configuration

Create a `.env` file in the project root for local development (it is git-ignored and loaded by `npm run server`) and fill the server-only values below. For the hosted Site, add these as runtime secrets through Sites environment settings, then deploy a new version. Do not put credentials into a `VITE_` variable or frontend code.

- `NEXAR_CLIENT_ID`, `NEXAR_CLIENT_SECRET`: Supply-enabled Nexar application.
- `DIGIKEY_CLIENT_ID`, `DIGIKEY_CLIENT_SECRET`: DigiKey application subscribed to Product Information v4 and able to use two-legged OAuth.
- `ANTHROPIC_API_KEY`: Claude API key for the server-side vision endpoint (`POST /api/vision`), which identifies the board and its components on an uploaded picture. Optional `ANTHROPIC_MODEL` overrides the default `claude-opus-5-5`. Pictures are sent as base64 JSON bodies of at most 6 MB and are never cached.

The adapters use the US market; offers keep their own currency (Mouser answers in INR for Indian accounts) and are converted to USD for comparison, then shown in INR or USD. Inventory on hand is independent of distributor availability. API results never overwrite inventory. Status means credentials are configured, not that access is verified. A successful search is the verification step.

API implementation references: [Nexar authorization](https://support.nexar.com/support/solutions/articles/101000471994), [Nexar query examples](https://support.nexar.com/support/solutions/articles/101000494582-nexar-playground-graphql-query-examples), [DigiKey authentication](https://developer.digikey.com/documentation), [DigiKey KeywordSearch](https://developer.digikey.com/products/product-information-v4/productsearch/keywordsearch).

## Scope of this version

The optional sample catalog, stock, lifecycle, prices, specs and alternatives are illustrative, not verified purchasing data. BOM prices come from the distributors at the time of the lookup; PCB prices are estimates until you enter your fab's quote. User-entered/imported rows are marked separately. All replacement candidates require datasheet, footprint, pinout, electrical, thermal and firmware review. Market availability is available only after supplier credentials are configured.

The reference board is a generated design, not an electrically validated board. Imported blueprints render what the file contains: KiCad boards carry real outline, copper and pads; centroid files carry positions only, so pads and body sizes are synthesised from package names and the board outline is the component extent plus a margin. Gerber, STEP, ODB++ and Altium binary files are not parsed; export a pick-and-place file from those tools. Picture blueprints yield detected shapes, not CAD data: no pads, copper or rotations, and labels that point with long leader lines may stay unattached unless Claude vision is connected. No electrical simulation or design-rule checking is performed.

Inventory is stored per browser in localStorage. This is not a shared warehouse database, and it has no multi-user stock transaction system, audit history or company roles. Export inventory to keep or share a copy. Hosted access is private through Sites; preserve that access while supplier secrets are active. Shared production use requires a database, access roles and durable API quota controls.

## Supplier keys

Set these in `.env` (server only, never prefixed with `VITE_`): `MOUSER_API_KEY`, `SERPAPI_KEY` (`GEMINI_API_KEYS` works the same way for Gemini: keys take turns when one reaches its quota or is rejected, and a model that answers "busy" is skipped for 5 minutes) (plus optional `SERPAPI_KEYS`, a comma-separated list of extra keys: when one key runs out of searches or is rejected, the same search moves on to the next and the spent key is skipped for an hour), `TME_TOKEN` and `TME_APP_SECRET`, `MASTER_SEARCH_API_KEY` and `MASTER_SEARCH_URL` (the search endpoint from your Master Electronics account manager, with `{mpn}` and `{key}` placeholders), plus the existing DigiKey and Nexar pairs. Restart `npm run server` after changing them. `MASTER_ORDER_API_KEY` is stored but no order is ever placed by the app.

## Deploy on Vercel

The Vercel workspace opens without sign-in by default. Inventory, board tools and production views run in the browser. Set `DIGIKEY_CLIENT_ID` and `DIGIKEY_CLIENT_SECRET` in Vercel to enable live DigiKey prices and stock in public mode. Other supplier and AI integrations require sign-in.

To enable sign-in and live integrations, set `REQUIRE_SIGNIN=1` in Vercel and configure hosted storage before deploying. Accounts, sign-in lockouts and the part-info cache use `public.semicobot_kv` in Supabase. Only `ADMIN_EMAIL` can create the first admin account.

1. Supabase → SQL Editor → run `supabase/schema.sql` once (table with row level security and no policies, plus the `semicobot_incr` counter; the public roles get no rights).
2. Put `SUPABASE_URL` and `SUPABASE_SECRET_KEY` (Project Settings → API Keys → secret key, `sb_secret_…`) in `.env`, then `node --env-file=.env scripts/check-supabase.mjs`: it writes, reads, counts and deletes one throwaway row, and with `SUPABASE_PUBLISHABLE_KEY` set confirms the public key can do none of that.
3. Optional: `node --env-file=.env scripts/push-accounts.mjs` copies the local accounts (`data/auth.json`) so the same people can sign in online (refuses to overwrite accounts already online unless `--replace`; prints counts only).
4. Deploy:

```sh
npx vercel login
npx vercel link
npx vercel env add REQUIRE_SIGNIN production
npx vercel env add SUPABASE_URL production
npx vercel env add SUPABASE_SECRET_KEY production --sensitive
npx vercel env add ADMIN_EMAIL production
npx vercel env add DIGIKEY_CLIENT_ID production   # and the other supplier keys from .env.example
npx vercel --prod
```

- The publishable key is never used by the server; it is safe in a browser only because row level security hides the table from it.
- `.vercelignore` keeps `.env`, `data/` (local accounts and cache), tests and scripts out of the upload: the Vercel CLI does not read `.gitignore`.
- Sign-up online: after the admin, nobody can join until `SIGNUP_ALLOW` lists addresses or `@domains` (`*` lets anyone join, which also lets anyone spend the supplier keys). Members the admin removes cannot sign up again unless `SIGNUP_ALLOW` names their address. Sign in soon after the first deploy, or copy the local accounts first, so nobody else claims the admin address.
- Wrong passwords: each attempt on a real account is counted before the check (5 per 15 minutes, shared by every function instance); unknown addresses take the same time and leave no rows.
- Upstash for Redis (`KV_REST_API_URL`, `KV_REST_API_TOKEN`) works instead of Supabase; Supabase wins when both are set.
- Limits: request bodies up to 4.5 MB (pictures are resized in the browser first), 300 s per API call (`vercel.json`). Free Supabase projects pause after 7 quiet days; the site then says so until the project is restored.

`node tests/browser.mjs` runs local workflow checks using Chrome at the macOS default path (override with `CHROME_PATH`; screenshots go to `WORK_DIR`, default `../../work`). It checks inventory search/edit/persistence, additions/import, Excel export, hover identification in 2D and 3D, blueprint import from the sample KiCad and pick-and-place files, adding a board part to inventory, BOM reference linking, board persistence, missing credentials, and 375/768/1024/1440 px layouts. `npm test` covers the API adapters and the blueprint parsers.

Live supplier calls cannot be verified until credentials are supplied. Automated API tests use fixtures and verify error cases and request construction.
